# My Atelier — 나만의 디지털 예술 작업실

React + TypeScript 기반의 개인 창작 웹앱입니다. 계정이나 서버 없이 브라우저에 작품을 보관합니다.

## 실행하기

1. [Node.js](https://nodejs.org/)의 LTS 버전(22 또는 24)을 설치하세요.
2. 이 폴더에서 터미널을 열고 처음 한 번 `npm ci`를 실행하세요.
3. `npm run dev`를 실행하고 터미널에 표시된 주소를 브라우저에서 여세요.
4. 다음에 사용할 때는 같은 폴더에서 `npm run dev`만 실행하면 됩니다. 종료는 터미널에서 Ctrl+C입니다.

서버는 파일을 제공하는 로컬 개발 서버이며, 작품을 업로드하는 백엔드는 없습니다. 저장소는 **브라우저·프로필·접속 주소(포트 포함)** 별로 구분됩니다. 동일한 주소로 접속해 주세요.

## 첫 작품 만들기

- **새 작품 만들기** → 이름과 규격 선택 → **캔버스 열기**.
- 이미지 업로드는 PNG/JPG/WebP, 파일당 25MB까지 지원합니다. 로고 삽입은 원본 이미지 파일을 별도 레이어로 배치하며 다시 그리지 않습니다.
- 텍스트 추가 후 글자를 두 번 클릭해 수정하세요. 오른쪽에서 한글 글꼴·크기·색·굵기·자간·행간·투명도를 바꿀 수 있습니다.
- 요소를 드래그하여 이동하고, 모서리 핸들로 크기를 조절하세요. 아래 레이어 목록으로 가려진 요소를 선택하고 순서를 바꿀 수 있습니다.
- 이미지 안에 이미 인쇄된 글자는 텍스트 레이어가 아닙니다. 그 글자나 배경을 자동으로 지우거나 고치지 않습니다. 새 텍스트와 도형은 다른 요소를 변경하지 않습니다.
- **작품 저장**을 누르면 IndexedDB에 편집 가능한 원본과 썸네일이 저장됩니다. 작품은 수동 저장, 영감 노트는 자동 저장입니다.
- **PNG 내보내기**는 확대 배율과 무관하게 선택한 원본 픽셀 크기로 저장합니다. A4는 794×1123px이며 인쇄용 300dpi 규격은 아닙니다. 고해상도 인쇄가 필요하면 자유 규격 2480×3508px을 사용하세요.
- 갤러리에서 즐겨찾기·복제·삭제, 초안/최종 완성 표시를 사용할 수 있습니다. 복제는 독립 작품이며 전체 버전 이력 및 이전 버전 복원은 2차 개발 대상입니다.

## 소중한 작품 보관

사이드바의 **작업실 백업**은 모든 작품의 편집 데이터·삽입 이미지·메모를 JSON 파일로 저장합니다. **백업 복원**으로 다른 브라우저에서도 가져올 수 있습니다. 같은 작품 ID는 확인 후 교체합니다. 브라우저 데이터를 삭제하거나 시크릿 모드를 종료하면 로컬 작품이 사라질 수 있으므로 정기적으로 백업하세요. PNG는 완성 이미지이며 편집 가능한 프로젝트 백업을 대신하지 않습니다. 작업을 떠나기 전 직접 저장해 주세요.

## 구현 범위

- 1차 MVP: 대시보드, 캔버스 레이어 편집, 한글 텍스트, 이미지/원본 로고 삽입, 실행 취소·다시 실행(최근 60단계), 확대/축소, 기본 정렬, A4/블로그/배너/자유 규격, 로컬 프로젝트 저장·복원, PNG 내보내기, 갤러리, 메모, 파일 백업.
- 준비 중: 브랜드 라이브러리, 템플릿, 전체 버전 관리, 일러스트 시안 비교. 해당 페이지에는 준비 중 안내를 표시합니다.
- AI 생성, Figma, 클라우드 동기화는 연결하지 않았습니다. API 키나 결제가 필요하지 않습니다. 확장 인터페이스는 `src/integrations.ts`에 정의돼 있으며 구현체는 없습니다.
- 정밀 편집은 PC 우선입니다. 모바일에서는 도구와 속성이 캔버스 위아래로 배치됩니다.
- 폰트는 앱에 포함되어 별도 Google Fonts 요청 없이 제공됩니다. 사용 기기마다 시스템 글꼴의 한글 지원이 다를 수 있어 편집기에서 포함된 Noto 글꼴을 선택할 수 있습니다.

## 구조와 개발

- `src/App.tsx`: 대시보드, 갤러리, 탐색 및 프로젝트 생성
- `src/Studio.tsx`: Fabric.js 편집기와 레이어·히스토리·내보내기
- `src/storage.ts`: IndexedDB 저장 및 파일 다운로드
- `src/integrations.ts`: 향후 연결을 위한 타입 계약
- `src/style.css`: 반응형 디자인
- `tests/atelier.spec.ts`: 실제 Chromium으로 실행하는 핵심 사용자 흐름 테스트

`npm run build`로 타입 검사와 배포용 빌드를 수행합니다. `npm run preview`로 빌드를 확인할 수 있습니다.

`npm test`는 시스템 Chromium을 사용합니다. 경로가 다르면 `CHROMIUM_PATH=/브라우저/경로 npm test`를 실행하세요. Playwright 브라우저를 사용하려면 `npx playwright install chromium` 후 설정 파일의 `executablePath`를 생략하세요.

브라우저 테스트는 레이어 편집·undo/redo·이미지 삽입·저장 후 새로고침 복원·원본 해상도 PNG 다운로드·메모·즐겨찾기·복제·백업 복원·모바일 화면을 검증합니다.

## 코딩 없이 웹사이트 게시하기

배포용 설정은 `netlify.toml`에 있습니다. Git 저장소를 Netlify에 연결하면 `npm run build` 결과인 `dist` 폴더를 게시합니다.

계정 연결 없이 이 환경에서 사용자 소유의 사이트 주소를 발급할 수는 없습니다. 직접 업로드하려면 다음 순서로 진행하세요.

1. `npm run build` 후 `python3 scripts/package-deploy.py`를 실행합니다.
2. 생성된 `my-atelier-deploy.zip`을 내려받습니다. 소스·계정 정보·작품 데이터는 포함되지 않습니다.
3. https://app.netlify.com/drop 에서 본인의 계정으로 로그인하고 ZIP 파일을 업로드합니다. ZIP 업로드를 지원하지 않는 화면이면 압축을 푼 폴더를 올립니다.
4. Netlify가 발급한 사이트 주소를 열고 사용합니다. 이후에도 같은 주소를 유지하세요.

웹사이트 파일은 공개되지만 작품은 접속한 브라우저에 저장됩니다. 현재 개발 주소의 작품은 새 사이트로 자동 이동하지 않습니다. 기존 작업실에서 백업한 JSON을 새 사이트의 ‘백업 복원’으로 가져오세요. 휴대폰과 PC 사이의 자동 동기화나 접속 제한은 이 버전에 없습니다.

## GitHub Pages로 사용하기

빌드된 웹사이트는 `atelier-site` 브랜치에, 개발 원본은 `atelier-deploy` 브랜치에 보관합니다. GitHub 저장소의 Settings → Pages에서 Source를 **Deploy from a branch**, Branch를 **atelier-site**, 폴더를 **/(root)**로 선택하고 Save를 누르세요. GitHub가 표시하는 게시 완료 주소로 접속합니다. 비공개 저장소의 Pages 사용 가능 여부는 GitHub 요금제에 따라 달라집니다.

작품 데이터는 사이트에 포함되지 않고 각 브라우저에 저장됩니다. 이후 업데이트도 같은 사이트 주소를 유지해야 기존 로컬 작품에 접근할 수 있습니다.
